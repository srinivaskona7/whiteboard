AWS · EC2 · request anatomy

Anatomy of an EC2 server request

One call — RunInstances — travels through six AWS layers before a single guest instruction executes. This page follows that request four ways: as a stack, as a timeline, as a decision tree, as a lifecycle, and finally as a sketch.

01

Where the request travels

Six layers, one direction. Each layer can refuse the request outright, and every refusal is reported upward as an error code — never as a partial success.

Read it downward. Layers 01–03 are refusals: a bad signature, an expired credential, or a missing ec2:RunInstances stops the request before it costs AWS anything. Layer 04 is the focal point — the only layer that converts a synchronous HTTP call into a durable job. Layers 05–06 are where an accepted request can still fail for capacity reasons.

02

The happy path, in time

The same six layers, but ordered. Five actors, eleven messages. Note where the API answers — the caller gets an instance id long before the instance is running.

The asymmetry that matters. Messages 1–8 are the synchronous request and take milliseconds. Message 8 returns pending — an id, not a machine. Everything after it is asynchronous, which is why scripts that assume “API returned, therefore SSH works” fail. Message 11 is the first honest signal that the OS finished booting.

03

Where it can fail

Three gates, three different error families. Which gate rejects you tells you who owns the fix — your signature, your policy, or AWS's spare capacity.

The order of the gates is the diagnostic. A signature failure means nothing was evaluated. An authorisation failure means the request was well-formed but the caller is not allowed. A capacity failure means AWS agreed to everything and still had no room. And the fourth box is the quiet one: RunInstances succeeded, the instance is running, and SSH is still refused — because the failure moved inside the guest, where the API cannot see it.

04

Instance lifecycle

Once the request is accepted, the instance is a state machine. Seven states, and only one of them is the one you actually wanted.

Two words that get conflated. pending means the control plane accepted the job. running means the hypervisor says a guest exists. Neither one means Linux finished booting — that is the status checks, which is why DescribeInstances and 2/2 are the only reliable readiness signal.

05

The same thing, hand-drawn

Everything above, reduced to what you would actually put on a whiteboard: six boxes and five arrows. If you can redraw this from memory, you understand the request.

Why draw it twice. The precise diagrams are for reading; this one is for remembering. Six boxes is the whole shape of the system: your code, one API, one policy check, one placement decision, one hypervisor, and the machine you asked for. Everything else — subnets, security groups, snapshots, user-data — is configuration that rides along inside those arrows.

06

Every abbreviation, expanded

Grouped by the layer it belongs to. The third column says what the term actually does in an EC2 request, not just what the letters stand for.

TermExpansionWhat it means here
Identity & access
IAMIdentity and Access ManagementThe policy engine that answers “may this principal perform this action on this resource”. Evaluated per call, never cached by your code.
SCPService Control PolicyAn organisation-level permission ceiling. It can only subtract — a broad identity policy still loses to a restrictive SCP.
STSSecurity Token ServiceIssues the temporary credentials behind every role. They expire, which is why long-running scripts need a refresh path.
SigV4Signature Version 4The HMAC scheme that signs the canonical request, the headers and a timestamp. Clock skew is the classic cause of a 403 here.
ARNAmazon Resource NameThe canonical id for anything: arn:aws:ec2:us-east-1:123456789012:instance/i-0abc….
KMSKey Management ServiceManaged keys for encrypted EBS volumes, snapshots and AMI copies. An unshared key makes an AMI unlaunchable even if it is visible.
MFAMulti-Factor AuthenticationA second factor the session must present before certain actions. Applies to the caller, not to the instance.
IMDSInstance Metadata ServiceThe link-local HTTP endpoint at 169.254.169.254 that tells a guest its own id, AZ, and role credentials.
IMDSv2Instance Metadata Service, version 2Requires a session token from a PUT before any GET. Defeats SSRF because forged requests cannot set the token header.
Compute & network
EC2Elastic Compute CloudThe virtual-server service. “Elastic” means the fleet is shared and the capacity is not reserved for you unless you pay for it.
AMIAmazon Machine ImageA launch recipe, not a disk: block-device mappings plus metadata such as architecture and UEFI boot data.
EBSElastic Block StoreNetwork-attached block storage. Latency can spike, which is why the default kernel command line relaxes the NVMe timeout.
ENAElastic Network AdapterThe PCIe NIC. If the ena driver is missing from the kernel and the initramfs, the guest has no network at all.
ENIElastic Network InterfaceThe virtual NIC object: MAC address, private IP, and the security groups attached to it. It survives instance termination if you detach it first.
NVMeNon-Volatile Memory ExpressThe storage protocol EBS volumes speak inside a Nitro guest. /dev/xvda is only an API-level alias for /dev/nvme0n1.
PCIePeripheral Component Interconnect ExpressThe only bus the guest sees. There is no SATA, IDE or floppy controller on Nitro, which is why old AMIs fail.
vCPUVirtual Central Processing UnitOne hyperthread on a physical core plus a fixed memory reservation. The instance type fixes how many PCIe functions you get.
AZAvailability ZoneAn isolated data-centre group inside a region. Snapshots are regional; volumes never cross an AZ boundary.
VPCVirtual Private CloudThe private network. The subnet, route table and internet gateway all live here, and all of them can block a launch.
SGSecurity GroupA stateful virtual firewall on an ENI. Allows nothing by default — including SSH, which is why a “running” instance can be unreachable.
EIPElastic IPA static public IPv4 address you can move between instances, unlike the ephemeral one assigned at launch.
HVMHardware Virtual MachineFull hardware emulation of a standard PC. Nitro only supports HVM; the old paravirtual mode is gone.
ASGAuto Scaling GroupReplaces unhealthy instances automatically. The reason a “terminated” instance sometimes comes back with a new id.
Storage & transport
S3Simple Storage ServiceWhere snapshots live as incremental block chains. An AMI is metadata pointing at them, not a file you download.
IOPSInput/Output Operations per SecondThe sizing unit for gp3 and io2 volumes. Root-volume IOPS decide how fast boot actually completes.
TLSTransport Layer SecurityThe encryption layer under HTTPS. The EC2 API requires 1.2 or newer.
HTTPSHyperText Transfer Protocol SecureHTTP inside TLS. Every AWS API call uses it — except IMDS, which is deliberately plain HTTP on a link-local address.
DNSDomain Name SystemResolves ec2.us-east-1.amazonaws.com for the caller, and the instance’s own ip-10-0-0-5.ec2.internal name after boot.
Boot & firmware
UEFIUnified Extensible Firmware InterfaceThe firmware interface Nitro guests boot with. It runs .efi executables from a FAT32 partition instead of a boot sector.
BIOSBasic Input/Output SystemThe legacy firmware UEFI replaced. Xen-era AMIs often still expect it, and hang on a Nitro host.
OVMFOpen Virtual Machine FirmwareThe open-source UEFI build (TianoCore/EDK2) AWS runs per guest. Same codebase as QEMU’s firmware.
POSTPower-On Self-TestUsed loosely here for firmware init: enumerate PCIe, initialise option ROMs, publish ACPI and DMI tables, pick a boot entry.
ACPIAdvanced Configuration and Power InterfaceThe table set that describes CPUs, interrupts and devices to the kernel — no hardware probing required.
DSDTDifferentiated System Description TableThe main ACPI bytecode blob: devices, power management, and the topology the kernel parses at boot.
MADTMultiple APIC Description TableLists the CPUs and interrupt controllers — this is how the kernel discovers and starts the other vCPUs.
SMBIOSSystem Management BIOSThe specification behind DMI: the identity card that dmidecode reads to report instance type and AZ.
GPTGUID Partition TableThe partition map firmware reads on the root volume. A GPT with no bootable entry means “No bootable device”.
MBRMaster Boot RecordThe legacy 512-byte partition table and first-stage bootstrap. Still fine for BIOS-boot images, invisible to UEFI.
ESPEFI System PartitionA FAT32 partition with a well-known type GUID. Firmware mounts it and runs \EFI\BOOT\BOOTX64.EFI.
GRUBGRand Unified BootloaderReads grub.cfg, loads the kernel and initramfs, and supplies the command line. Generated, never hand-edited.
bzImagebig zImageThe compressed kernel file: a legacy setup header plus a compressed 64-bit payload with an EFI stub.
initramfsinitial RAM filesystemA cpio archive the kernel unpacks into tmpfs. It carries the drivers needed to mount the real root.
initrdinitial RAM diskThe older block-device form of the same idea — you needed a filesystem driver just to read the thing holding your drivers.
cpiocopy in/outThe archive format initramfs is packed in, chosen because the kernel can unpack it with no driver at all.
GDTGlobal Descriptor TableThe segment descriptor table built early in start_kernel(), before memory management is usable.
IDTInterrupt Descriptor TableMaps interrupt vectors to handlers. Built alongside the GDT so the CPU can take faults and timers.
APICAdvanced Programmable Interrupt ControllerThe interrupt controller used to wake secondary vCPUs with INIT-SIPI during SMP bring-up.
SMPSymmetric Multi-ProcessingBringing every vCPU online. Until it finishes, the guest is effectively single-threaded.
VFSVirtual File SystemThe kernel layer behind mount. VFS: Unable to mount root fs on unknown-block(0,0) means the root= spec resolved to no device.
PIDProcess IdentifierPID 1 is the first userspace process — /sbin/init, normally systemd. switch_root replaces the initramfs’s PID 1 with the real one.
Formats & interfaces
APIApplication Programming InterfaceThe contract behind RunInstances. EC2 uses an RPC-style API, not a REST one — every call is an action name plus parameters.
SDKSoftware Development KitLanguage bindings that build the signed request for you. boto3 is the Python one and does its own retries.
CLICommand Line InterfaceThe aws command. It is a thin wrapper over the same API, so it inherits every policy and quota limit.
IaCInfrastructure as CodeTerraform, CloudFormation, CDK — declaring servers in files so the request is reviewable and repeatable.
JSONJavaScript Object NotationThe response format of the EC2 API. Partial failures appear inside it, not as HTTP errors.
YAMLYAML Ain’t Markup LanguageThe format of #cloud-config user-data. Indentation is significant, and a tab silently breaks it.
UUIDUniversally Unique IdentifierThe 128-bit id a filesystem gets at creation. root=UUID=… is why a restored snapshot with a stale id fails to boot.
CIDRClassless Inter-Domain RoutingSubnet notation such as 10.0.0.0/24. Its size decides how many free IPs a launch can consume.
Operations & security
SSHSecure ShellThe remote shell you are trying to reach. Working SSH is the practical definition of “the instance is up”.
SSMSystems ManagerRuns commands through an outbound agent instead of inbound SSH — the fix when a security group blocks port 22.
EICEC2 Instance ConnectPushes a short-lived public key through the API, so no static key has to live on the instance.
SSRFServer-Side Request ForgeryThe attack IMDSv2 exists to block: tricking your app into fetching metadata credentials on its own network path.
HAHigh AvailabilitySurviving the loss of an AZ. One instance is never HA, no matter how healthy its status checks are.
RTORecovery Time ObjectiveHow long you can afford to be down. It decides whether you rebuild from an AMI or restore a snapshot.
