AWS EC2 · Linux boot chain

How a Linux instance boots on EC2

Eight stages from RunInstances to first-boot configuration, laid out by the layer that owns each hand-off — the AWS control plane, the hypervisor, firmware, the kernel, and userspace.

The two halves

  • Steps 1–2 run entirely in the AWS control plane — nothing of yours executes yet
  • The AMI's root volume is cloned and attached before any guest instruction runs
  • Step 3 is the first code that executes inside your instance

Where boots stall

  • GRUB — missing or corrupt /boot, or a stale root=UUID
  • Kernel — initramfs with no ENA or NVMe driver, so the root device never appears
  • cloud-init — no route to 169.254.169.254, or an IMDSv2 token refused

Where to look

  • Console → Actions → Monitor and troubleshoot → Get system log
  • Serial console, for GRUB and early kernel output
  • Status checks: instance reachability first, then system
