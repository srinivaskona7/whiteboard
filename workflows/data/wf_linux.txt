= lnx-hello-files | Module 2: hello.txt: create, view, copy, move, rename, delete | 1 | doc | Follow one file, hello.txt, through the everyday file commands. Each command changes the folder, and ls shows how.
> Make a folder and a file | edit
text: mkdir creates a folder (-p makes parents too), echo prints text and > writes it into a file, creating it. The file now holds Hello Srinivas plus an end-of-line character.
cmd: mkdir -p ~/lab/hello

text: cat prints the whole file, head and tail the first or last lines, wc counts lines, words and bytes, less lets you scroll. The file is 15 bytes: 14 characters plus the newline.
cmd: cat hello.txt
cmd: head -n 1 hello.txt
cmd: wc hello.txt

out: Hello Srinivas\nHello Srinivas\n 1  2 15 hello.txt\nHello Srinivas$

text: > overwrites, >> appends. A very common mistake is using > when you meant >>.
cmd: echo "Welcome to Linux" >> hello.txt
cmd: cat -n hello.txt

out: 1  Hello Srinivas\n2  Welcome to Linux\noops

text: cp makes a second file with the same content. -i asks before overwriting and -a copies a whole folder keeping all details.

cmd: cp hello.txt backup.txt
cmd: cp -i hello.txt backup.txt
cmd: ls
out: backup.txt  hello.txt

text: mv both moves and renames: same folder means rename, a different folder means move. There is no separate rename command.

out: .:\ndocs  hello.txt\n\n./docs:\ngreeting.txt

cmd: rm -i docs/greeting.txt

= lnx-hello-perms | Module 3: Who can read hello.txt? Permissions, owner and groups | 1 | lock | Read the ls -l permission string, change it with chmod in letters and numbers, change owner with chown and see what umask does.
> Read the permission string | eye
text: -rw-r--r-- has ten characters. The first is the type (- file, d folder). Then three sets of three: owner, group, others, each r (read), w (write), x (execute).
cmd: mkdir -p ~/lab && cd ~/lab && echo "Hello Srinivas" > hello.txt
cmd: ls -l hello.txt
cmd: stat -c '%A %a %U:%G %n' hello.txt
out: -rw-r--r-- 1 srinivas srinivas 15 Nov  4 10:10 hello.txt\n-rw-r--r-- 644 srinivas:srinivas hello.txt
> Numbers: r=4 w=2 x=1 | hash
text: Add the digits per set. rw- is 4+2=6, r-- is 4, so 644. rwx is 7. A secret file should be 600 and a script 755.
cmd: chmod 600 hello.txt
cmd: ls -l hello.txt
cmd: chmod 644 hello.txt
out: -rw------- 1 srinivas srinivas 15 Nov  4 10:10 hello.txt
> Letters: add or remove one right | edit
text: u is owner, g group, o others, a all. + adds, - removes, = sets exactly. This is easier when you want to change just one bit.
cmd: chmod g+w hello.txt
cmd: chmod o-r hello.txt
cmd: chmod a+x hello.txt
cmd: ls -l hello.txt
out: -rwxrw---x 1 srinivas srinivas 15 Nov  4 10:10 hello.txt
> Folders need x to enter | folder
text: On a folder, r lets you list names, w lets you create and delete inside, x lets you enter it. Without x on the folder you cannot reach files in it even if the file is readable.
cmd: mkdir private && chmod 700 private
cmd: ls -ld private
cmd: chmod 000 private && ls private
cmd: chmod 700 private
out: drwx------ 2 srinivas srinivas 4096 Nov  4 10:12 private\nls: cannot open directory 'private': Permission denied
> Change owner and group | users
text: chown changes who owns a file and needs root. chgrp changes only the group. Group sharing is the safe way to let a team use a folder.
cmd: sudo chown root:root hello.txt
cmd: ls -l hello.txt
cmd: cat hello.txt
cmd: sudo chown srinivas:srinivas hello.txt
out: -rwxrw---x 1 root root 15 Nov  4 10:10 hello.txt\ncat: hello.txt: Permission denied
> umask: the default for new files | sliders
text: A new file starts as 666 and a new folder as 777; umask removes bits. umask 022 gives files 644 and folders 755.
cmd: umask
cmd: umask 077
cmd: touch secret.txt && mkdir secretdir && ls -ld secret.txt secretdir
cmd: umask 022
out: 0022\n-rw------- 1 srinivas srinivas 0 Nov  4 10:14 secret.txt\ndrwx------ 2 srinivas srinivas 4096 Nov  4 10:14 secretdir
> Special bits and sudo | shield
text: A script can run only if it has x. The setuid bit (4xxx) runs a program as its owner, like passwd. Use sudo for one command as root instead of logging in as root.
cmd: ls -l /usr/bin/passwd
cmd: sudo -l
cmd: id
out: -rwsr-xr-x 1 root root 59976 Nov  4 2024 /usr/bin/passwd\nuid=1000(srinivas) gid=1000(srinivas) groups=1000(srinivas),27(sudo)

text: grep prints lines that match. -i ignores case, -n shows line numbers, -r searches folders, -v inverts, -c counts, -w matches whole words.

cmd: grep -rn "error" .
cmd: grep -c error old/app.log

text: Put commands together with the pipe. sort orders lines, uniq -c counts neighbours, so sort first. This lists which words start each line of the log and how often.

cmd: find . -name "*.log" -exec ls -l {} \;
cmd: find . -name "*.txt" | xargs grep -l Srinivas
cmd: find . -name "*.log" -print0 | xargs -0 echo would-delete
out: -rw-r--r-- 1 srinivas srinivas 44 Nov  4 10:20 ./old/app.log\n./hello.txt\nwould-delete ./old/app.log

= lnx-hello-redirect | Module 5: Streams, redirects and pipes with hello.txt | 2 | pipeline | Understand stdin, stdout and stderr, send each one where you want, and chain commands.
> Three streams | pipeline
text: Every program has standard input (0), standard output (1) and standard error (2). Normal results go to 1, error messages to 2. Both show on the screen unless you redirect them.
cmd: cd ~/lab && echo "Hello Srinivas" > hello.txt
cmd: cat hello.txt nofile.txt
out: Hello Srinivas\ncat: nofile.txt: No such file or directory
> Redirect output | edit
text: > sends stdout to a file, >> appends, 2> sends only the errors, 2>&1 sends errors to the same place as stdout, &> sends both.
cmd: cat hello.txt nofile.txt > out.txt 2> err.txt
cmd: cat out.txt err.txt
cmd: cat hello.txt nofile.txt &> both.txt
cmd: cat nofile.txt 2> /dev/null; echo "silent, exit $?"
out: Hello Srinivas\ncat: nofile.txt: No such file or directory\nsilent, exit 1
> Feed input from a file | download
text: < makes a file the standard input. A here-document (<<) writes several lines straight into a command.
cmd: wc -l < hello.txt
cmd: cat > multi.txt <<'EOF'\nline one\nline two\nline three\nEOF
cmd: sort -r < multi.txt
out: 1\nline two\nline three\nline one
> Pipe one command into the next | link
text: | connects stdout of the left command to stdin of the right one. Each tool does one small job. tee also saves what passes through.
cmd: cat multi.txt | grep line | wc -l
cmd: ls /etc | head -n 3 | tee first3.txt
cmd: cat first3.txt | tr a-z A-Z
out: 3\nadduser.conf\nalternatives\napparmor\nADDUSER.CONF\nALTERNATIVES\nAPPARMOR
> Exit codes: success, failure and chaining | check
text: Every command ends with a number: 0 means success. $? shows the last one. && runs the next command only on success, || only on failure, ; always.
cmd: grep -q Srinivas hello.txt && echo found || echo missing
cmd: grep -q nobody hello.txt && echo found || echo missing
cmd: false; echo "exit code $?"
out: found\nmissing\nexit code 1

= lnx-hello-script | Module 6: Turn hello.txt into a script: variables, if, loops, functions | 2 | code | Write hello.sh, make it executable, read arguments, test conditions, loop over files and set a safe mode.
> A first script | edit
text: A script is a text file of commands. The first line, #!/usr/bin/env bash, says which interpreter runs it.
cmd: cd ~/lab && printf '#!/usr/bin/env bash\necho "Hello Srinivas"\n' > hello.sh
cmd: cat hello.sh
cmd: ./hello.sh
out: bash: ./hello.sh: Permission denied
> Make it executable and run it | play
text: chmod +x adds the execute right. ./ means run the file in the current folder. You can also run bash hello.sh without it.
cmd: chmod +x hello.sh
cmd: ./hello.sh
cmd: bash hello.sh
out: Hello Srinivas\nHello Srinivas
> Variables and arguments | sliders
text: NAME=value sets a variable with no spaces around =. $1 is the first argument, $# the count, "$@" all arguments. Always quote variables.
cmd: cat > hello.sh <<'EOF'\n#!/usr/bin/env bash\nname="${1:-Srinivas}"\necho "Hello $name, you gave $# argument(s)"\nEOF
cmd: ./hello.sh
cmd: ./hello.sh India Asia
out: Hello Srinivas, you gave 0 argument(s)\nHello India, you gave 2 argument(s)
> Conditions | gate
text: if [ test ]; then ... fi. Useful tests: -f file exists, -d folder, -z empty text, -eq number equals, == text equals. Use [[ ]] in bash.
cmd: cat > check.sh <<'EOF'\n#!/usr/bin/env bash\nif [[ -f hello.txt ]]; then\n  echo "hello.txt exists, $(wc -c < hello.txt) bytes"\nelse\n  echo "hello.txt is missing"; exit 1\nfi\nEOF
cmd: bash check.sh
out: hello.txt exists, 15 bytes
> Loops and functions | retry
text: for repeats over a list, while repeats while a test is true, a function groups steps you reuse.
cmd: cat > loop.sh <<'EOF'\n#!/usr/bin/env bash\ngreet() { echo "Hello $1"; }\nfor n in Srinivas India Linux; do greet "$n"; done\ni=1; while [[ $i -le 3 ]]; do echo "count $i"; i=$((i+1)); done\nEOF
cmd: bash loop.sh
out: Hello Srinivas\nHello India\nHello Linux\ncount 1\ncount 2\ncount 3
> Safer scripts | shield
text: set -euo pipefail stops on the first error, on unset variables and on failures inside pipes. Check scripts with shellcheck.
cmd: printf '#!/usr/bin/env bash\nset -euo pipefail\ncd /nonexistent\necho "never printed"\n' > safe.sh
cmd: bash safe.sh; echo "exit $?"
cmd: shellcheck hello.sh
out: safe.sh: line 3: cd: /nonexistent: No such file or directory\nexit 1

= lnx-hello-remote | Module 7: Send hello.txt to another server: ssh keys, scp and rsync | 2 | upload | Make a key pair, install it on a server, log in without a password, copy hello.txt both ways and keep folders in sync.
> Create a key pair | key
text: A key pair has a private key (never share) and a public key (safe to give). ed25519 is short and strong. A passphrase protects the private key if the laptop is stolen.
cmd: ssh-keygen -t ed25519 -C "srinivas@laptop" -f ~/.ssh/id_ed25519
cmd: ls -l ~/.ssh
out: -rw------- 1 srinivas srinivas  411 Nov  4 10:30 id_ed25519\n-rw-r--r-- 1 srinivas srinivas  100 Nov  4 10:30 id_ed25519.pub
> Install the public key on the server | upload
text: ssh-copy-id appends your public key to ~/.ssh/authorized_keys on the server. After this you do not need the account password.
cmd: ssh-copy-id -i ~/.ssh/id_ed25519.pub srinivas@server.example.com
cmd: ssh srinivas@server.example.com 'hostname; whoami'
out: Number of key(s) added: 1\nweb-01\nsrinivas
> Save the connection in ~/.ssh/config | doc
text: A named host saves typing. After this ssh web works, and so do scp and rsync.
cmd: cat >> ~/.ssh/config <<'EOF'\nHost web\n  HostName server.example.com\n  User srinivas\n  IdentityFile ~/.ssh/id_ed25519\n  ServerAliveInterval 30\nEOF
cmd: chmod 600 ~/.ssh/config
cmd: ssh web 'uptime'
> Copy hello.txt with scp | copy
text: scp copies over SSH. The remote path comes after a colon. Copy to the server, then copy something back.
cmd: scp hello.txt web:/tmp/hello.txt
cmd: ssh web 'cat /tmp/hello.txt'
cmd: scp web:/etc/hostname ./remote-hostname.txt
out: hello.txt                    100%   15     0.6KB/s   00:00\nHello Srinivas
> Keep a folder in sync with rsync | retry
text: rsync sends only what changed, so the second run is fast. Use -n for a dry run first. A trailing slash on the source means the contents.
cmd: rsync -avn ~/lab/ web:/tmp/lab/
cmd: rsync -av ~/lab/ web:/tmp/lab/
cmd: rsync -av --delete ~/lab/ web:/tmp/lab/
risk: 1
> Harden the server's SSH | shield
text: Once keys work, turn off password logins and root login on the server. Test the config first and keep a second session open.
cmd: sudo sshd -t && echo "config ok"
cmd: sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
cmd: sudo systemctl reload ssh
out: config ok

= lnx-nftables | Module 8: The modern firewall: nftables and ufw | 3 | firewall | Read the rules, write a small default-deny ruleset with nft, test it safely and make it persistent.
> nftables replaces iptables | firewall
text: nftables is the modern packet filter in the kernel. iptables commands on new systems are often a thin layer over it. One tool, nft, handles IPv4, IPv6 and bridges.
cmd: nft --version
cmd: sudo nft list ruleset | head -n 15
out: nftables v1.0.9 (Old Doris #3)\ntable inet filter {\n  chain input {\n    type filter hook input priority filter; policy accept;\n  }\n}
> The model: tables, chains, rules | layers
text: A table holds chains, a chain holds rules. A base chain attaches to a hook (input, forward, output) and has a policy. Each rule matches packets and gives a verdict such as accept or drop.
cmd: sudo nft add table inet lab
cmd: sudo nft 'add chain inet lab input { type filter hook input priority 0; policy accept; }'
cmd: sudo nft list table inet lab
> Write a default-deny ruleset | lock
text: Keep established connections, allow loopback, allow SSH from one network and web, then drop the rest. Put SSH first so you cannot lock yourself out.
cmd: sudo nft add rule inet lab input ct state established,related accept
cmd: sudo nft add rule inet lab input iif lo accept
cmd: sudo nft add rule inet lab input ip saddr 192.168.1.0/24 tcp dport 22 accept
cmd: sudo nft add rule inet lab input tcp dport { 80, 443 } accept
cmd: sudo nft 'add chain inet lab input { policy drop; }'
risk: 1
> See counters and test | search
text: Add counter to a rule to see how many packets matched. Test from another machine, and check the drop with a port you did not open.
cmd: sudo nft add rule inet lab input counter
cmd: sudo nft list chain inet lab input
cmd: nc -zv server.example.com 80 22 8080
out: Connection to server.example.com 80 port [tcp/http] succeeded!\nConnection to server.example.com 8080 port [tcp/*] timed out
> Save and load at boot | save
text: Export the running rules to /etc/nftables.conf and enable the service. flush ruleset at the top makes reloads repeatable.
cmd: sudo nft list ruleset | sudo tee /etc/nftables.conf
cmd: sudo nft -c -f /etc/nftables.conf && echo "syntax ok"
cmd: sudo systemctl enable --now nftables
> The easy way: ufw | shield
text: ufw is a simple front end for Ubuntu. Allow SSH before enabling it. Do not mix hand-written nft rules and ufw on the same host.
cmd: sudo ufw allow OpenSSH
cmd: sudo ufw allow 80,443/tcp
cmd: sudo ufw enable
cmd: sudo ufw status numbered
out: Status: active\n\n     To                         Action      From\n[ 1] OpenSSH                    ALLOW IN    Anywhere\n[ 2] 80,443/tcp                 ALLOW IN    Anywhere

= lnx-boot | Linux boot process, end to end | 2 | power | Seven steps from power button to login prompt: firmware, boot loader, kernel, initramfs, systemd and services.
> Firmware: BIOS or UEFI | chip
text: Power on starts the firmware. It runs the power-on self-test (POST), initialises basic hardware and picks a boot device. UEFI loads a boot loader from the EFI System Partition (ESP) using entries stored in NVRAM. Legacy BIOS loads the boot sector (MBR) of the first bootable disk.
cmd: [ -d /sys/firmware/efi ] && echo "UEFI boot" || echo "Legacy BIOS boot"
cmd: sudo efibootmgr -v
cmd: findmnt /boot/efi
out: $ [ -d /sys/firmware/efi ] && echo "UEFI boot" || echo "Legacy BIOS boot"\nUEFI boot\n$ findmnt /boot/efi\nTARGET    SOURCE         FSTYPE OPTIONS\n/boot/efi /dev/nvme0n1p1 vfat   rw,relatime
note: efibootmgr works only on UEFI systems. Boot order and Secure Boot are changed in the firmware setup screen.
> Boot loader: GRUB | menu
text: The firmware starts the boot loader, usually GRUB 2 (often through shim for Secure Boot). GRUB reads its configuration, shows the menu, loads the chosen kernel and the initramfs into memory and passes the kernel command line.
cmd: cat /proc/cmdline
cmd: ls -lh /boot
cmd: sudo grep -E '^\s*(menuentry|linux|initrd)' /boot/grub/grub.cfg | head -n 6
out: $ cat /proc/cmdline\nBOOT_IMAGE=/boot/vmlinuz-6.8.0-45-generic root=UUID=3f2a-example ro quiet splash
note: Change settings in /etc/default/grub, then run update-grub (Debian, Ubuntu) or grub2-mkconfig -o /boot/grub2/grub.cfg (RHEL 9). Do not edit grub.cfg by hand.
> Kernel initialisation | chip
text: GRUB runs the kernel. It decompresses itself, sets up memory management and the scheduler, detects hardware, starts built-in drivers and mounts the initramfs as a temporary root filesystem. Everything it reports goes to the kernel ring buffer.
cmd: uname -r
cmd: sudo dmesg | head -n 12
cmd: journalctl -k -b --no-pager | head -n 12

= lnx-kernel-sysctl | Kernel modules, sysctl and limits | 3 | chip | Load a module, tune a kernel setting temporarily and permanently, and raise a file limit.
> List loaded modules | chip
text: Modules are drivers loaded into the running kernel. lsmod lists them and modinfo describes one.
cmd: lsmod | head -n 6
cmd: modinfo br_netfilter | head -n 5
out: $ lsmod | head -n 6\nModule                  Size  Used by\nbr_netfilter           32768  0\nbridge                311296  1 br_netfilter
> Load and unload one | swap
text: modprobe loads a module with its dependencies; -r removes it. To load one at every boot, list it in /etc/modules-load.d/.
cmd: sudo modprobe br_netfilter
cmd: lsmod | grep br_netfilter
cmd: echo br_netfilter | sudo tee /etc/modules-load.d/k8s.conf
> Read kernel settings | search
text: sysctl reads and writes values under /proc/sys. The same value can be read as a file.
cmd: sysctl net.ipv4.ip_forward
cmd: cat /proc/sys/net/ipv4/ip_forward
cmd: sysctl -a 2>/dev/null | grep -c .
out: $ sysctl net.ipv4.ip_forward\nnet.ipv4.ip_forward = 0
> Change a setting now and forever | sliders
text: sysctl -w changes it until the next reboot. To make it permanent write a file in /etc/sysctl.d and reload all of them with sysctl --system.
cmd: sudo sysctl -w net.ipv4.ip_forward=1
cmd: echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/99-forward.conf
cmd: sudo sysctl --system | tail -n 3
risk: 1
> Raise the open file limit | up
text: ulimit -n is the limit of open files for the current shell. Servers with many connections need more. For services set LimitNOFILE in the systemd unit; for logins use /etc/security/limits.d.
cmd: ulimit -n
cmd: printf '[Service]\nLimitNOFILE=65536\n' | sudo tee /etc/systemd/system/myapp.service.d/limits.conf
cmd: sudo systemctl daemon-reload
out: $ ulimit -n\n1024
note: Change one setting at a time and note the old value so you can revert.
